# 灰尘负载测试台

Windows WPF 上位机，使用 .NET 10、[NModbus](https://github.com/NModbus/NModbus) 和 SQLite。底部导航包含状态监控、手动窗口、参数设置、历史数据、设备管理、联系我们和权限管理。

## 运行

```powershell
dotnet run --project .\DustLoadScada.csproj
```

也可以构建 Release，再启动 `bin\Release\net10.0-windows\DustLoadScada.exe`。目标电脑需安装 .NET 10 Windows Desktop Runtime。

1. 软件启动后进入模拟模式。点击「开始模拟测试」，按当前配方依次运行正常负载和灰尘负载测试。扫码栏可留空自动生成条码，也可输入条码后按 Enter。勾选「模拟不合格」可查看不合格样例。
2. 打开「参数设置」可查看和切换配方。点击「新建」，在弹窗中填写配方名称和产品型号，确认后会复制所选配方的测试参数并选中新配方。编辑参数后点击「保存」。模拟模式点击「启用配方」，真机模式点击「启用并下发 PLC」。当前配方在下发前更新，写入在后台进行。PLC 的 Y11（可在系统设置修改）置 1 后，上位机触发扫码枪，按配方的开始序号和对比长度截取条码并与产品型号逐字符比较；对比长度为 0 时使用产品型号长度。测试期间手动动作和检测开关不可用；配方编辑与下发不受运行状态限制。
3. 在「历史数据」按日期和条码查询。起止日期均包含当日，留空表示不限。点击「导出 CSV」后可选择本地文件夹或 U 盘。CSV 使用带 BOM 的 UTF-8。
4. 在「权限管理」输入固定管理员 `admin` 的密码 `123456`。登录在程序内校验。仅点位（地址）编辑需要管理员登录；配方、系统设置、删除记录、手动、复位、检测开关和 PLC 读写测试等均无需登录。

本机数据默认保存在 `%LOCALAPPDATA%\DustLoadScada\station.db`，记录保留测试来源、时间和条码等信息。

历史表和 CSV 的前两列为二维码和时间，后面是 17 项测试数据。二维码列显示扫码内容，时间列显示本机时区下的存档时间。电压用 V，电流用 A，功率用 W，转速用 r/min。模拟模式会生成全部测试项。旧记录及未配置点位的项目在表格中显示为「—」，CSV 留空。

在「历史数据 → 地址配置」可查看 19 项测试数据的 Modbus 地址和数据类型。管理员可点击对应行的「编辑」。正常电压、电流、分阶段电流／功率／转速判定和地刷灯灭判定需要按现场点表填写，地址留空可停用该项。跑马灯灭相机判定默认 HM2，头灯跑马灯相机判定默认 HM1，可覆盖或留空停用。读数按「工程值 = 原始值 × 倍率」换算：带单位的整数默认倍率 0.01（即原值乘以 0.01），Float32 默认倍率 1，倍率可在点位弹窗修改并随点位保存。新增点位配置地址后随轮询实时读取，并在记录触发线圈置 1 时随整轮结果存档。正常／灰尘功率、正常／灰尘转速、方向判定及总判定与状态监控共用点位。

同一 Tab 的「二维码」行可设置 Modbus 起始地址和连续寄存器数量。默认从 `TelemetryAddress + 26` 起读取 16 个寄存器。读取使用 PLC 当前寄存器区，文本采用 UTF-8，每字高字节在前，遇到 NUL 结束。配置用于后续状态监控、历史记录和 CSV 导出。

「记录触发」可设置独立的可写 Modbus 线圈，例如 `M11` 或零基地址 `11`。配置后，PLC 写入一轮完整结果，再将线圈置 1 并保持结果稳定。上位机读到 1 后读取该轮结果，数据库提交后写回 0。读取或保存失败时保持 1 并重试，清零失败也会重试。同一站点下，二维码、产品型号、各项测试值和总判定都相同的结果只会保存一次；运行时间和实时电压不参与比较。每轮仍须提供有效总判定。PLC 模式只按记录触发线圈存档；运行状态 3（测试OK）、4（测试NG）不会自动存档。留空则 PLC 测试结果不存档。

监控读数、历史采集、手动控制、检测开关、配方参数、二维码、记录触发和复位的地址编辑共用一个弹窗，按点位类型显示地址、数据类型、反馈地址或寄存器数量。监控、配方与历史采集点位统一使用「寄存器地址 + 数据类型 + 倍率」三项：数据类型支持 Int16、UInt16、Int32、UInt32、Float32，配方点位的数据类型也可在此修改并随点位保存；倍率按「工程值 = 原始值 × 倍率」换算，默认沿用原有换算，可自定义。选择 Float32 时隐藏倍率字段（直接读写工程量，不使用倍率）。弹窗会预览有效地址范围、默认／自定义状态、当前倍率及 PLC 数据区；字段错误贴近输入显示。冲突校验按所选类型的实际寄存器字数检查重叠，配置保存在弹窗内完成，失败时保留输入并显示原因。连接 PLC 后可执行只读读取测试，查看原始值及适用点位的解析值；读取测试不会写入线圈或配方。各点位仍分别保存配置，原有留空规则和二维码「恢复默认」功能不变。

### 编辑测试读数点位

状态监控的实时电压、总判定、正常功率、灰尘功率、功率差、功率判定、正常转速、灰尘转速、转速差、转速判定、转速方向判定，以及测试读数表格上方的跑马灯灭相机判定和头灯跑马灯相机判定，右上角都有铅笔按钮。跑马灯灭相机判定仅在检测开关「相机灯灭开关」反馈为开时显示，头灯跑马灯相机判定仅在「相机灯灭亮开关」反馈为开时显示；开关关闭或反馈未知时隐藏。点击可设置该项的 Modbus 起始地址和数据类型，支持 Int16、UInt16、Int32、UInt32 和 Float32。未修改的项继续使用默认偏移，已保存的地址使用从 0 开始的绝对协议地址，并保存在本机数据库中。每个数据目录对应一套点位配置。

点位编辑需管理员登录。接入 PLC 后会使用保存的配置。监控点位统一沿用 `UseInputRegisters` 指定的寄存器区及 `LowWordFirst` 指定的字顺序。电压和功率的整数原值默认倍率 0.01（乘以 0.01）后分别以 V 和 W 显示，Float32 默认倍率 1 直接读取工程量；倍率可在弹窗修改。转速使用 r/min，四项可配置判定沿用 0 待判定、1 合格、2 不合格的编码。

状态监控顶部状态栏有两个独立地址：状态文字旁的铅笔按钮设置「运行状态」寄存器（默认 `TelemetryAddress + 0`，即 D0，Int16）；右侧运行时间旁的铅笔按钮设置「计时触发」线圈（可填 M、X、Y 等，只读）。计时由上位机完成：线圈为 1 期间计时，变 0 时停止并保留最后时间，再次变 1 时清零重新计时；未配置时运行时间保持 0。

运行状态码：1 设备待机、2 设备运行中、3 设备测试OK、4 设备测试NG、5 急停被按下、6 扫码内容错误、7 电压不在范围内。状态栏直接显示对应文字，其他值显示「未知运行状态」。2 时锁定手动和检测开关；5、6、7 及未知值按故障处理，锁定手动、检测开关和配方下发。配方编辑、点位编辑与复位不随运行状态锁定，联锁由 PLC 保证；1、3、4 视为空闲。

映射到监控区外的点位会按连续地址分组读取。上位机在分组读取前后核对运行状态和整段监控区。PLC 应在测试完成后锁存结果，直到该轮结果可以被上位机读取。

## 设备管理

每个进程共享一个相机连接、一个 PLC 实例和一个扫码枪连接。通过底部「设备管理」入口配置设备。页面顶部的「保存全部配置」先统一校验已填写的设备参数，再保存相机、PLC 和扫码枪配置；主机或 COM 口留空的设备跳过保存并保留原配置。校验失败时不写入任何配置；存储失败会提示已保存的设备，不会将部分成功显示为全部成功。保存不会连接、断开或重连设备，需使用各设备独立的「连接／断开」按钮应用参数。应用启动时只连接已配置的设备：数据目录存在有效的 `plc.json` 时直接连接 PLC，否则保持模拟模式；已保存的相机 IP 不为空时自动连接相机；已保存的 COM 口在系统中存在时自动打开扫码枪一次，串口不存在、打开失败或断开后不重试，需在设备页手动连接。

- 相机作为 TCP 客户端连接相机的 IP 和端口，可发送 UTF-8 文本并选择行尾，接收区显示最近收到的字节。具体指令和消息格式按相机协议填写。启动时连接失败或连接后断线，状态显示「重连中」，每 2 秒重试一次。点击「断开」后停止重连。
- 「手动窗口」中的「相机拍照」按钮通过相机 TCP 发送 `start`（不带行尾），等待 3 秒内的回复：`OK` 显示拍照成功，`fail` 或超时、未连接、其他回复均弹窗提示失败。模拟与 PLC 模式均可直接使用，测试运行期间不可用。该按钮不写 PLC 线圈，其余手动按钮按住写 1、松开写 0。
- PLC 使用 Modbus TCP。设备页可配置 IP、端口和站号。连接后默认支持读写，具体操作按账号权限、点位和设备状态执行。其他参数在数据目录的 `plc.json` 中维护，示例见 `plc.example.json`。每个独立 PLC 使用固定且唯一的 `StationId`。已连接的 PLC 发生断线时会继续尝试重连，主动断开则切回模拟模式。
- PLC 卡片的「读写测试」使用当前 PLC 连接和站号。支持按零基地址读取保持寄存器、输入寄存器、线圈和离散输入，一次最多 125 项。PLC 在线、未运行测试且未处于故障时，可写单个保持寄存器原始值或线圈，无需登录。读取寄存器会同时显示十进制和十六进制。
- 扫码枪使用 Windows COM 串口，可配置波特率、数据位、校验位、停止位和流控。连接后可按 UTF-8 字符串发送指令，支持附加 CR、LF 或 CRLF，也可切换到 HEX 直接发送原始字节；发送格式、行尾和内容随设备配置一起保存。FM430 默认启动指令为 `01 54 04`，停止指令为 `01 50 04`，均不附加行尾。接收端按 CR 或 LF 分隔条码，以 UTF-8 解码；「最近接收」显示最近条码，并附累积收到的原始字节（HEX）与 ASCII 文本，没有结束符的回复也能看到。相机的发送文本/行尾、PLC 读写测试的数据区/起始地址/读取数量/写入值，以及相机最近接收、扫码枪最近接收、PLC 测试结果，都会随「保存全部配置」一起保存，重新打开页面或重启后恢复（显示框在无新数据时回退到上次保存的内容）。PLC 触发的扫码会暂停被动接收，执行一次触发扫描后恢复接收。无效 UTF-8 或超过 4096 字节的条码会显式报错并关闭连接，不截断或静默丢弃。

### NLS-FM430 串口类库

底层扫码通讯已提取到独立的 [Newland.Fm430 类库](Libraries/Newland.Fm430/Newland.Fm430.csproj)，目标为 `net10.0`，仅依赖 `System.IO.Ports`，不依赖 WPF、PLC 或数据库。现有设备页通过适配层使用类库，界面与测试流程不变。

```csharp
using Newland.Fm430;

await using var scanner = new Fm430Scanner(new Fm430SerialOptions("COM3"));
await scanner.ConnectAsync();
string barcode = await scanner.ScanAsync(TimeSpan.FromSeconds(4));
Console.WriteLine(barcode);
```

- 默认串口参数为 9600、8N1、无流控，可通过 `Fm430SerialOptions` 指定已配置的串口参数。
- `ConnectAsync` / `DisconnectAsync`：打开、关闭串口；不自动重连。`DisposeAsync` 会取消接收并释放串口。
- `StartScanningAsync` / `StopScanningAsync`：仅发送默认启动／停止指令；`SendAsync` 发送原始字节，不追加任何内容。
- `ScanAsync`：清除旧条码、半包和串口未读数据，触发一次扫码并等待新条码；等待超时或取消时尝试发送停止指令。停止或关闭失败会保留原始错误一并抛出，不返回空串或假成功。
- `ReadBarcodeAsync`：被动接收下一条码，支持感应／连续模式；`Timeout.InfiniteTimeSpan` 表示持续等待。CR、LF 和 CRLF 均可分帧，UTF-8 跨包字符及一次收到多条码均会保留。
- 同一实例只能有一个未完成的 `ScanAsync` 或 `ReadBarcodeAsync`；并发接收会明确报错。各异步接口可传入 `CancellationToken`；串口原生写入最长等待 3 秒，已经开始的原生打开／写入会在返回后完成取消或清理。

使用 `ScanAsync` 前，按 FM430 手册第 31、36 页设置为「电平触发模式」并使能「串行触发指令」，启动／停止指令保持默认值。按第 211、227 页使能前后缀总开关和 CRLF 结束符，关闭其他前后缀及数据打包；含中文的二维码需将输出编码设置为 UTF-8。类库不会自行修改设备参数。读码未成功信息默认禁用，保持此设置可由上位机超时判断；开启时 `NG` 等失败文本会原样返回，调用方须自行区分。

```powershell
dotnet build .\Libraries\Newland.Fm430\Newland.Fm430.csproj -c Release
dotnet test .\Tests\Newland.Fm430.Tests\Newland.Fm430.Tests.csproj -c Release
```

测试使用模拟串口验证指令、分帧、取消、超时和断线清理，不访问现场 COM 口；实际接线及设备设置仍需实机验证。

## 系统设置

底部「系统设置」按「运行时间统计」与「扫码触发与写回」两张卡片展示。统计卡片显示当前累计时间及状态，地址内联填写保存；扫码卡片的三个地址（触发线圈、二维码写回、比对结果）改为只读显示加铅笔按钮，点开与监控/配方共用的点位弹窗逐个编辑保存，弹窗提供预览、字段报错、只读测试与重叠校验，但这三处不加数据类型/倍率（线圈、字符串块与协议码无换算意义）。无需登录即可修改和保存，累计时间清零仍需确认；监控/配方等点位地址铅笔需管理员登录。

- 运行时间统计：填写运行状态线圈地址（如 `M10`，也可填 `Y10`、`X0` 或零基十进制线圈地址）。连接 PLC 后每个轮询周期读取该线圈，为 1 时累加运行时间，为 0 时暂停。累计值以「时:分:秒」显示在状态监控页的「累计运行时间」卡片中。
- 累计值保存在数据库中，程序重启后继续累加。计时期间每 10 秒保存一次，线圈变为 0、PLC 断开或关闭程序时也会保存。通讯中断期间和模拟模式下不计时。
- 「累计时间清零」需确认后执行。地址留空保存即停止统计，已累计的时间保留。
- 扫码触发与写回：默认读取线圈 `Y11`，为 1 时触发一次扫码；地址留空可停用。二维码写入前先清空 `D4000` 起的 80 个连续保持寄存器，再以 UTF-8、高字节在前按实际长度动态写入（最多 80 个寄存器 / 160 字节），超长条码报错，不截断。比对结果写入 `D3`：`1` 匹配、`2` 不匹配。扫码及 PLC 通讯失败时保留触发并重试；二维码和比对结果写入成功后才将触发线圈写 0，写回失败会重试同一条码而不重复扫码。三个地址均可经铅笔弹窗修改，保存到本机数据目录。这组地址独立于监控区中用于显示 PLC 条码的二维码点位。

## Modbus TCP 接入

以下寄存器布局是本工程的**示例接口**，根据参考图定义。项目交付时缺少现场 PLC 点表。现场可让 PLC 提供下述连续数据区，也可依据实际点表修改 `PlcLayout` 和读写逻辑。寄存器及线圈地址使用从零开始的协议偏移。读取使用 FC03，`UseInputRegisters` 为 `true` 时改用 FC04。

### 监控区

从 `TelemetryAddress` 读取 64 个寄存器。多字数值默认高字在前，`LowWordFirst` 可切换为低字在前。文本使用 UTF-8，每字高字节在前，NUL 结尾或占满字段，空余补零。判定值为 0 待判定、1 合格、2 不合格。

| 字偏移 | 内容 | 类型或比例 |
| --- | --- | --- |
| 0 | 运行状态（默认位置，可改址） | Int16，1–7 见上文状态码 |
| 1 | 保留 | 不再读取 |
| 2–3 | 保留 | 不再读取 |
| 4–5 | 保留 | 不再读取，运行时间由上位机按计时触发线圈计时 |
| 6–7 | 实时电压 | Int32，实际 V × 100 |
| 8–9 / 10–11 / 12–13 | 正常功率 / 灰尘功率 / 功率差 | Int32，实际 W × 100 |
| 14–15 / 16–17 / 18–19 | 正常转速 / 灰尘转速 / 转速差 | Int32，r/min |
| 20 / 21 / 22 / 23 | 功率 / 转速 / 总判定 / 转速方向 | UInt16，判定值 |
| 24 | 保留 | 不再读取 |
| 25 | 地刷灯亮判定 | UInt16，判定值 |
| 26–41 / 42–57 | 扫码信息 / 产品型号 | 各 32 字节 |
| 58 | 手动反馈 | bit 0–12 对应下列命令顺序 |
| 59–63 | 保留 | 填 0 |

测试完成时 PLC 应发布一份完整且稳定的快照，并提供有效总判定。上位机按站点和结果内容去重。分组读取前后核对运行状态和整段监控区，任一变化则丢弃本次读数。现场需要在复位或下一轮开始前保留已完成快照，确保上位机在轮询间隔及预期断线期间能够读取。测试时序、联锁、传感器采样及真机判定由 PLC 执行。

### 配方区

`RecipeAddress` 为配方块起点。软件使用 FC16 一次写入 64 字，PLC 应在空闲且通过联锁后读取并应用配方。界面提示代表收到 Modbus 写寄存器确认。多字顺序和字符串编码与监控区一致。

参数界面的 16 个数值点位旁可编辑各自的保持寄存器起始地址、数据类型和倍率。使用从 0 开始的协议地址，设置独立于配方值保存在本机。留空回到默认地址。数据类型默认沿用原编码（电压／功率差为 Float32，次数为 UInt16，其余为 Int32），可改为 Int16、UInt16、Int32、UInt32 或 Float32；倍率按「工程值 = 原始值 × 倍率」换算（下发原始值 = 配方值 ÷ 倍率），默认沿用原有比例，Float32 不使用倍率。改址或改类型后按实际寄存器字数校验重叠。下发时跳过已改址点位腾出的寄存器。未设置 `RecipeAddress` 时，配置完全部 16 个地址即可下发数值参数。产品型号和扫码字段通过原配方块传输。

配方参数页和新建配方窗口中的 Float32 电压、功率差上下限固定显示 4 位小数（例如 `28.0000`）。此格式仅影响显示，不改变数值的数据类型和下发编码；时间和整数字段保持原有显示格式。

两处窗口均可选择并保存「相机配方」：头灯-跑马灯对应 `switch 1`，头灯对应 `switch 2`，跑马灯对应 `switch 3`。命令中间为一个空格，不加行尾，不增加 PLC 寄存器。点击「启用配方」或「启用并下发 PLC」时，先通过设备管理页面中已连接的相机 TCP 发送对应命令。模拟模式同样发送。发送前会丢弃相机先前发来的数据：连接空闲约 50 ms 后才发送命令并开始等待回复；若相机 1 秒内持续发送数据，则不发送命令并提示。发送后最多等待 3 秒相机回复：返回 `OK`（不区分大小写，允许带行尾）才启用配方并下发 PLC。返回 `fail`、超时、回复无法识别、相机未连接或连接中断时，不启用配方，也不下发 PLC。旧配方默认选择头灯-跑马灯。

有自定义地址时，上位机按连续地址分段发送 FC16。PLC 应等全部数据到齐后再应用，分段写入失败时界面会提示可能已有部分参数写入。

| 字偏移 | 内容 | 类型或比例 |
| --- | --- | --- |
| 0 | 布局版本 | UInt16，固定为 1 |
| 1–4 / 5–8 / 9–12 | 电压 / 功率差 / 转速差，每组下限在前、上限在后 | Float32（V）/ Float32（W）/ Int32（r/min） |
| 13–16 | 正常及灰尘测试时间 | Int32，整数秒，原值下发 |
| 17–20 / 21–24 | 开机及档位动作时长 / 开机及档位间隔 | Int32，秒 × 10（0.1 秒单位） |
| 25 / 26 | 开机及档位次数 | UInt16 |
| 27–28 / 29–30 | 报警时间 / 跑马灯灭时间 | Int32，秒 × 10（0.1 秒单位） |
| 31 | 开始序号 | UInt16，从 1 开始计数；上位机按此字符位置提取条码 |
| 32–47 | 产品型号 | 32 字节 UTF-8 |
| 48 | 对比长度 | UInt16；上位机与完整产品型号比较，0 表示采用产品型号长度 |
| 49–55 | 保留 | 填 0 |
| 56–63 | 保留 | 填 0 |

### 手动命令

手动窗口使用信捷 XD3 PLC 的 M 线圈作为按钮输入，用 Y 线圈反馈实际输出。按下用 FC05 写 1，松开用 FC05 写 0；指针移出按钮、窗口失去焦点或离开手动页时也会释放按钮。反馈通过 FC01 分组读取，通讯失败时显示「反馈未知」。清零失败后会尝试在通讯恢复时重发 0。PLC 需要自行处理联锁和通讯中断时的输出释放。

「全部归零」向全部手动输出（M50–M62）写入 0，确认后执行，用于一键释放；未按下的线圈也会写 0（幂等）。

每个按钮旁的铅笔可编辑写入地址和反馈地址。地址按信捷 XD3 规则自动换算，也可直接填写从 0 开始的十进制 Modbus 地址。写入地址不能位于 X/Y 区。地址配置保存在本机数据库。地址编辑需管理员登录，手动操作本身无需登录。

| 软元件 | 范围 | Modbus 地址 | 类型 |
| --- | --- | --- | --- |
| M | M0–M7999 | 0–7999 | 线圈 |
| X（八进制） | X0–X77、X10000–X11177、X20000–X20177、X30000–X30077 | 0x5000、0x5100、0x58D0、0x5BF0 起 | 线圈 |
| Y（八进制） | Y0–Y77、Y10000–Y11177、Y20000–Y20177、Y30000–Y30077 | 0x6000（24576）、0x6100、0x68D0、0x6BF0 起 | 线圈 |
| S | S0–S1023 | 0x7000（28672）起 | 线圈 |
| HM | HM0–HM959 | 0xC100（49408）起 | 线圈／保持寄存器 |
| D | D0–D7999 | 0–7999 | 保持寄存器 |
| HD | HD0–HD999 | 0xA080（41088）起 | 保持寄存器 |

### 检测开关与复位

参数设置页的检测开关通过 `Commands` 配置写入线圈。打开用 FC05 写 1，关闭写 0。PLC 程序应按开关电平处理，并将实际状态写入监控区反馈字的以下位。界面按反馈显示开、关或未知。

三个检测开关右侧的铅笔可分别设置写入线圈和反馈线圈。可输入 `M`/`S`/`HM` 写入点、`Y`/`X`/`M` 反馈点或从 0 开始的十进制线圈地址。设置保存在本机。写入留空使用 `Commands` 的地址，反馈留空使用下表的监控反馈位。填写反馈线圈后用 FC01 读取该线圈。保存地址只更新映射，操作开关时才写入 PLC。

| 位 | 命令 | 界面名称 |
| --- | --- | --- |
| 10 | `cameraOn` | 相机灯灭亮开关 |
| 11 | `cameraOff` | 相机灯灭开关 |
| 12 | `scanner` | 扫码开关 |

状态监控页「复位」旁的铅笔可设置独立的复位请求线圈，支持 `M` 编号或零基十进制地址。留空使用 `plc.json` 中的 `Commands.reset`，两处都为空时真机复位不可用。保存地址只更新本机映射。复位为点动按钮：按下时上位机用 FC05 写 1，松开时写 0，不做前置读取检查，也不因运行状态禁用（通讯正常且配置了复位地址即可按下）。PLC 程序应校验设备状态和联锁，在请求为 1 期间处理复位并更新实际反馈。
