# 灰尘负载测试台

Windows WPF 上位机，使用 .NET 10、[NModbus](https://github.com/NModbus/NModbus) 和 SQLite。底部导航包含状态监控、手动窗口、参数设置、历史数据、设备管理、联系我们和权限管理。

## 运行

```powershell
dotnet run --project .\DustLoadScada.csproj
```

也可以构建 Release，再启动 `bin\Release\net10.0-windows\DustLoadScada.exe`。目标电脑需安装 .NET 10 Windows Desktop Runtime。

1. 软件启动后进入模拟模式。点击「开始模拟测试」，按当前配方依次运行正常负载和灰尘负载测试。扫码栏可留空自动生成条码，也可输入条码后按 Enter。勾选「模拟不合格」可查看不合格样例。
2. 打开「参数设置」可查看和切换配方。点击「新建」，在弹窗中填写配方名称和产品型号，确认后会复制所选配方的测试参数并选中新配方。编辑参数后点击「保存」。模拟模式点击「启用配方」，真机模式点击「启用并下发 PLC」。当前配方在下发前更新，写入在后台进行。「开始长度」用于校验条码长度，0 表示不限。测试期间配方和手动动作不可用。
3. 在「历史数据」按日期和条码查询。起止日期均包含当日，留空表示不限。点击「导出 CSV」后可选择本地文件夹或 U 盘。CSV 使用带 BOM 的 UTF-8。
4. 在「权限管理」创建首个负责人账号，密码至少 8 个字符。负责人可管理用户、编辑配方和删除选中历史记录。操作员登录后可执行已开放的 PLC 手动命令及复位。首个账号创建前，模拟模式允许试用配方编辑。

本机数据默认保存在 `%LOCALAPPDATA%\DustLoadScada\station.db`。模拟记录和 PLC 记录在历史表中显示各自来源。

### 编辑测试读数点位

状态监控的实时电压、总判定、正常功率、灰尘功率、功率差、功率判定、正常转速、灰尘转速、转速差、转速判定和转速方向判定右上角都有铅笔按钮。点击可设置该项的 Modbus 起始地址和数据类型，支持 Int16、UInt16、Int32、UInt32 和 Float32。未修改的项继续使用默认偏移，已保存的地址使用从 0 开始的绝对协议地址，并保存在本机数据库中。每个数据目录对应一套点位配置。

真机模式下请用负责人账号在测试结束后编辑。首个账号创建前可在模拟模式设置点位，接入 PLC 后会使用保存的配置。监控点位统一沿用 `UseInputRegisters` 指定的寄存器区及 `LowWordFirst` 指定的字顺序。电压和功率的整数原值乘以 0.01 后分别以 V 和 W 显示，Float32 直接读取工程量。转速使用 r/min，四项可配置判定沿用 0 待判定、1 合格、2 不合格的编码。

映射到监控区外的点位会按连续地址分组读取。上位机在分组读取前后核对测试阶段、流水号及测量有效位。PLC 应在测试完成后锁存结果，直到该轮结果可以被上位机读取。

## 设备管理

每个进程共享一个相机连接、一个 PLC 实例和一个扫码枪连接。设备页和右上角「通讯设置」打开同一个入口。点击「保存」保存当前连接参数，点击「连接」使用页面中的参数。应用启动时进入模拟模式，外设由操作员连接。

- 相机作为 TCP 客户端连接相机的 IP 和端口，可发送 UTF-8 文本并选择行尾，接收区显示最近收到的字节。具体指令和消息格式按相机协议填写。
- PLC 使用 Modbus TCP。设备页可配置 IP、端口、站号和写入开关。其他参数在数据目录的 `plc.json` 中维护，示例见 `plc.example.json`。每个独立 PLC 使用固定且唯一的 `StationId`。已连接的 PLC 发生断线时会继续尝试重连，主动断开则切回模拟模式。
- PLC 卡片的「读写测试」使用当前 PLC 连接和站号。支持按零基地址读取保持寄存器、输入寄存器、线圈和离散输入，一次最多 125 项。负责人在 PLC 在线、未运行测试、未处于故障且当前连接允许写入时，可写单个保持寄存器原始值或线圈。读取寄存器会同时显示十进制和十六进制。
- 扫码枪使用 Windows COM 串口，可配置波特率、数据位、校验位、停止位和流控。连接后可按 UTF-8 字符串发送指令，支持附加 CR、LF 或 CRLF，也可切换到 HEX 直接发送原始字节，例如 `02 41 03`。接收端按 CR 或 LF 分隔条码，以 UTF-8 解码并显示最近条码。条码在设备页用于通讯检查，测试流程继续使用 PLC 提供的扫码信息。

## Modbus TCP 接入

以下寄存器布局是本工程的**示例接口**，根据参考图定义。项目交付时缺少现场 PLC 点表。现场可让 PLC 提供下述连续数据区，也可依据实际点表修改 `PlcLayout` 和读写逻辑。寄存器及线圈地址使用从零开始的协议偏移。读取使用 FC03，`UseInputRegisters` 为 `true` 时改用 FC04。

### 监控区

从 `TelemetryAddress` 读取 64 个寄存器。多字数值默认高字在前，`LowWordFirst` 可切换为低字在前。文本使用 UTF-8，每字高字节在前，NUL 结尾或占满字段，空余补零。判定值为 0 待判定、1 合格、2 不合格。

| 字偏移 | 内容 | 类型或比例 |
| --- | --- | --- |
| 0 | 布局版本 | UInt16，固定为 1 |
| 1 | 测试状态 | 0 待机、1 正常、2 灰尘、3 完成、4 故障 |
| 2–3 | 测试流水号 | UInt32 |
| 4–5 | 测试用时 | UInt32，毫秒 |
| 6–7 | 实时电压 | Int32，实际 V × 100 |
| 8–9 / 10–11 / 12–13 | 正常功率 / 灰尘功率 / 功率差 | Int32，实际 W × 100 |
| 14–15 / 16–17 / 18–19 | 正常转速 / 灰尘转速 / 转速差 | Int32，r/min |
| 20 / 21 / 22 / 23 | 功率 / 转速 / 总判定 / 转速方向 | UInt16，判定值 |
| 24 | 测量有效位 | bit 0 正常样本有效，bit 1 灰尘样本有效 |
| 25 | 地刷灯亮判定 | UInt16，判定值 |
| 26–41 / 42–57 | 扫码信息 / 产品型号 | 各 32 字节 |
| 58 | 手动反馈 | bit 0–12 对应下列命令顺序 |
| 59–63 | 保留 | 填 0 |

测试完成时 PLC 应发布一份完整且稳定的快照，包含非零且在该站点内持久唯一的流水号和有效总判定。上位机按站点和流水号去重。现场需要在复位或下一轮开始前保留已完成快照，确保上位机在轮询间隔及预期断线期间能够读取。测试时序、联锁、传感器采样及真机判定由 PLC 执行。

### 配方区

`RecipeAddress` 为配方块起点。软件使用 FC16 一次写入 64 字，PLC 应在空闲且通过联锁后读取并应用配方。界面提示代表收到 Modbus 写寄存器确认。多字顺序和字符串编码与监控区一致。

参数界面的 16 个数值点位旁可编辑各自的保持寄存器起始地址。使用从 0 开始的协议地址，设置独立于配方值保存在本机。留空回到默认地址。下发时跳过已改址点位腾出的寄存器。未设置 `RecipeAddress` 时，配置完全部 16 个地址即可下发数值参数。产品型号和扫码字段通过原配方块传输。

有自定义地址时，上位机按连续地址分段发送 FC16。PLC 应等全部数据到齐后再应用，分段写入失败时界面会提示可能已有部分参数写入。

| 字偏移 | 内容 | 类型或比例 |
| --- | --- | --- |
| 0 | 布局版本 | UInt16，固定为 1 |
| 1–4 / 5–8 / 9–12 | 电压 / 功率差 / 转速差，每组下限在前、上限在后 | Int32，V × 100 / W × 100 / r/min |
| 13–16 | 正常及灰尘测试时间 | Int32，毫秒 |
| 17–20 / 21–24 | 开机及档位动作时长 / 开机及档位间隔 | Int32，毫秒 |
| 25 / 26 | 开机及档位次数 | UInt16 |
| 27–28 / 29–30 | 报警时间 / 跑马灯灭时间 | Int32，毫秒 |
| 31 | 扫码长度 | UInt16，0 为不限 |
| 32–47 / 48–55 | 产品型号 / 扫码结束字符 | 32 / 16 字节 |
| 56–63 | 保留 | 填 0 |

### 手动命令

手动窗口使用汇川 PLC 的 M 线圈作为按钮输入，用 Y 线圈反馈实际输出。按下用 FC05 写 1，松开用 FC05 写 0。窗口失去焦点或离开手动页时也会释放按钮。反馈通过 FC01 分组读取，通讯失败时显示「反馈未知」。清零失败后会尝试在通讯恢复时重发 0。PLC 需要自行处理联锁和通讯中断时的输出释放。

每个按钮旁的铅笔可编辑写入地址和反馈地址。支持汇川符号（如 `M50`、`Y10`）或从 0 开始的十进制线圈地址。Y 编号为八进制，Y0 的协议地址为 64512，Y10 为 64520。地址配置保存在本机数据库。真机写入需登录，并在 `plc.json` 中将 `EnableWrites` 和 `EnableManualWrites` 都设为 `true`。仅查看 Y 反馈时可保持写入关闭。地址换算见[汇川 H5U Modbus 协议说明](https://m.itlevne.com/data/upload/file/20210226/1614318717267400.pdf)。

| 写入 | 按钮 | 读取反馈 |
| --- | --- | --- |
| M50 | 通电 | Y0 |
| M51 | 压头气缸 | Y1 |
| M52 | 上压气缸 | Y2 |
| M53 | 通电平移 | Y3 |
| M54 | 开关气缸 | Y4 |
| M55 | 模式气缸 | Y5 |
| M56 | 灰尘模拟气缸 | Y6 |
| M57 | 地刷通电气缸 | Y7 |
| M58 | 编码器气缸 | Y10 |
| M59 | 扫码启动 | Y11 |

手动页按参考图显示以上十个按钮。原点表的 M60–M62 和 Y12–Y14 映射仍保存在软件中。

### 检测开关与复位

参数设置页的检测开关通过 `Commands` 配置写入线圈。打开用 FC05 写 1，关闭写 0。PLC 程序应按开关电平处理，并将实际状态写入监控区反馈字的以下位。界面按反馈显示开、关或未知。

三个检测开关右侧的铅笔可分别设置写入线圈和反馈线圈。可输入 `M` 写入点、`Y` 反馈点或从 0 开始的十进制线圈地址。设置保存在本机。写入留空使用 `Commands` 的地址，反馈留空使用下表的监控反馈位。填写反馈线圈后用 FC01 读取该线圈。保存地址只更新映射，操作开关时才写入 PLC。

| 位 | 命令 | 界面名称 |
| --- | --- | --- |
| 10 | `cameraOn` | 相机灯灭亮开关 |
| 11 | `cameraOff` | 相机灯灭开关 |
| 12 | `scanner` | 扫码开关 |

`reset` 为独立的复位请求线圈。上位机用 FC01 检查上次请求是否已清除，再用 FC05 置位。PLC 程序应校验设备状态和联锁，处理请求，清除请求位，并更新实际反馈。默认 `EnableWrites` 为 `false`。点表和 PLC 逻辑确认后，将其改为 `true` 并填写允许的命令地址与配方地址。
