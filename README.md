# 灰尘负载测试台

Windows WPF 上位机，使用 .NET 10、[NModbus](https://github.com/NModbus/NModbus) 和 SQLite。底部导航包含状态监控、手动窗口、参数设置、历史数据、设备管理、联系我们和权限管理。

## 运行

```powershell
dotnet run --project .\DustLoadScada.csproj
```

也可以构建 Release，再启动 `bin\Release\net10.0-windows\DustLoadScada.exe`。目标电脑需安装 .NET 10 Windows Desktop Runtime。

1. 软件启动后进入模拟模式。点击「开始模拟测试」，按当前配方依次运行正常负载和灰尘负载测试。扫码栏可留空自动生成条码，也可输入条码后按 Enter。勾选「模拟不合格」可查看不合格样例。
2. 打开「参数设置」可查看和切换配方。点击「新建」，在弹窗中填写配方名称和产品型号，确认后会复制所选配方的测试参数并选中新配方。编辑参数后点击「保存」。模拟模式点击「启用配方」，真机模式点击「启用并下发 PLC」。当前配方在下发前更新，写入在后台进行。扫码的开始序号和对比长度作为配方参数下发，具体扫码规则由 PLC 执行；上位机不据此判断条码是否包含产品型号。测试期间配方和手动动作不可用。
3. 在「历史数据」按日期和条码查询。起止日期均包含当日，留空表示不限。点击「导出 CSV」后可选择本地文件夹或 U 盘。CSV 使用带 BOM 的 UTF-8。
4. 在「权限管理」输入固定管理员 `admin` 的密码 `123456`。登录在程序内校验。管理员可编辑配方和点位、删除选中历史记录，以及执行已开放的 PLC 手动命令和复位。

本机数据默认保存在 `%LOCALAPPDATA%\DustLoadScada\station.db`，记录保留测试来源、时间和条码等信息。

历史表和 CSV 的前两列为二维码和时间，后面是 17 项测试数据。二维码列显示扫码内容，时间列显示本机时区下的存档时间。电压用 V，电流用 A，功率用 W，转速用 r/min。模拟模式会生成全部测试项。旧记录及未配置点位的项目在表格中显示为「—」，CSV 留空。

在「历史数据 → 地址配置」可查看 17 项测试数据的 Modbus 地址和数据类型。管理员可在测试结束后点击对应行的「编辑」。正常电压、电流、分阶段电流／功率／转速判定和地刷灯灭判定需要按现场点表填写，地址留空可停用该项。正常电压和电流的整数原值乘以 0.01，Float32 直接读取工程量。新增点位在 PLC 发布测试完成状态后读取，保存的配置用于后续采集。正常／灰尘功率、正常／灰尘转速、方向判定及总判定与状态监控共用点位。

同一 Tab 的「二维码」行可设置 Modbus 起始地址和连续寄存器数量。默认从 `TelemetryAddress + 26` 起读取 16 个寄存器。读取使用 PLC 当前寄存器区，文本采用 UTF-8，每字高字节在前，遇到 NUL 结束。配置用于后续状态监控、历史记录和 CSV 导出。

「记录触发」可设置独立的可写 Modbus 线圈，例如 `M11` 或零基地址 `11`。配置后，PLC 写入一轮完整结果，再将线圈置 1 并保持结果稳定。上位机读到 1 后读取该轮结果，数据库提交后写回 0。读取或保存失败时保持 1 并重试，清零失败也会重试，同一站点的同一流水号只会保存一次。每轮仍须提供非零且唯一的流水号和有效总判定。留空恢复按测试完成状态存档。

监控读数、历史采集、手动控制、检测开关、配方参数、二维码和记录触发的地址编辑共用一个弹窗，按点位类型显示地址、数据类型、反馈地址或寄存器数量。校验错误在弹窗内提示；各点位仍分别保存配置，原有留空规则和二维码「恢复默认」功能不变。

### 编辑测试读数点位

状态监控的实时电压、总判定、正常功率、灰尘功率、功率差、功率判定、正常转速、灰尘转速、转速差、转速判定和转速方向判定右上角都有铅笔按钮。点击可设置该项的 Modbus 起始地址和数据类型，支持 Int16、UInt16、Int32、UInt32 和 Float32。未修改的项继续使用默认偏移，已保存的地址使用从 0 开始的绝对协议地址，并保存在本机数据库中。每个数据目录对应一套点位配置。

请用管理员账号在测试结束后编辑点位。接入 PLC 后会使用保存的配置。监控点位统一沿用 `UseInputRegisters` 指定的寄存器区及 `LowWordFirst` 指定的字顺序。电压和功率的整数原值乘以 0.01 后分别以 V 和 W 显示，Float32 直接读取工程量。转速使用 r/min，四项可配置判定沿用 0 待判定、1 合格、2 不合格的编码。

映射到监控区外的点位会按连续地址分组读取。上位机在分组读取前后核对测试阶段、流水号及测量有效位。PLC 应在测试完成后锁存结果，直到该轮结果可以被上位机读取。

## 设备管理

每个进程共享一个相机连接、一个 PLC 实例和一个扫码枪连接。通过底部「设备管理」入口配置设备。点击「保存」保存当前连接参数，点击「连接」使用页面中的参数。应用启动时只连接已配置的设备：数据目录存在有效的 `plc.json` 时直接连接 PLC，否则保持模拟模式；已保存的相机 IP 不为空时自动连接相机；已保存的 COM 口在系统中存在时自动打开扫码枪一次，串口不存在、打开失败或断开后不重试，需在设备页手动连接。

- 相机作为 TCP 客户端连接相机的 IP 和端口，可发送 UTF-8 文本并选择行尾，接收区显示最近收到的字节。具体指令和消息格式按相机协议填写。启动时连接失败或连接后断线，状态显示「重连中」，每 2 秒重试一次。点击「断开」后停止重连。
- PLC 使用 Modbus TCP。设备页可配置 IP、端口和站号。连接后默认支持读写，具体操作按账号权限、点位和设备状态执行。其他参数在数据目录的 `plc.json` 中维护，示例见 `plc.example.json`。每个独立 PLC 使用固定且唯一的 `StationId`。已连接的 PLC 发生断线时会继续尝试重连，主动断开则切回模拟模式。
- PLC 卡片的「读写测试」使用当前 PLC 连接和站号。支持按零基地址读取保持寄存器、输入寄存器、线圈和离散输入，一次最多 125 项。管理员在 PLC 在线、未运行测试且未处于故障时，可写单个保持寄存器原始值或线圈。读取寄存器会同时显示十进制和十六进制。
- 扫码枪使用 Windows COM 串口，可配置波特率、数据位、校验位、停止位和流控。连接后可按 UTF-8 字符串发送指令，支持附加 CR、LF 或 CRLF，也可切换到 HEX 直接发送原始字节，例如 `02 41 03`。接收端按 CR 或 LF 分隔条码，以 UTF-8 解码并显示最近条码。条码在设备页用于通讯检查，测试流程继续使用 PLC 提供的扫码信息。

## 系统设置

底部「系统设置」入口仅管理员可修改。

- 运行时间统计：填写运行状态线圈地址（如 `M10`，也可填 `Y10` 或零基十进制线圈地址）。连接 PLC 后每个轮询周期读取该线圈，为 1 时累加运行时间，为 0 时暂停。累计值以「时:分:秒」显示在状态监控页的「累计运行时间」卡片中。
- 累计值保存在数据库中，程序重启后继续累加。计时期间每 10 秒保存一次，线圈变为 0、PLC 断开或关闭程序时也会保存。通讯中断期间和模拟模式下不计时。
- 「累计时间清零」需确认后执行。地址留空保存即停止统计，已累计的时间保留。

## Modbus TCP 接入

以下寄存器布局是本工程的**示例接口**，根据参考图定义。项目交付时缺少现场 PLC 点表。现场可让 PLC 提供下述连续数据区，也可依据实际点表修改 `PlcLayout` 和读写逻辑。寄存器及线圈地址使用从零开始的协议偏移。读取使用 FC03，`UseInputRegisters` 为 `true` 时改用 FC04。

### 监控区

从 `TelemetryAddress` 读取 64 个寄存器。多字数值默认高字在前，`LowWordFirst` 可切换为低字在前。文本使用 UTF-8，每字高字节在前，NUL 结尾或占满字段，空余补零。判定值为 0 待判定、1 合格、2 不合格。

| 字偏移 | 内容 | 类型或比例 |
| --- | --- | --- |
| 0 | 布局版本 | UInt16，固定为 1 |
| 1 | 测试状态 | 0 待机、1 正常、2 灰尘、3 完成、4 故障 |
| 2–3 | 测试流水号 | UInt32 |
| 4–5 | 测试用时 | UInt32，毫秒 |
| 6–7 | 实时电压 | Int32，实际 V × 100 |
| 8–9 / 10–11 / 12–13 | 正常功率 / 灰尘功率 / 功率差 | Int32，实际 W × 100 |
| 14–15 / 16–17 / 18–19 | 正常转速 / 灰尘转速 / 转速差 | Int32，r/min |
| 20 / 21 / 22 / 23 | 功率 / 转速 / 总判定 / 转速方向 | UInt16，判定值 |
| 24 | 测量有效位 | bit 0 正常样本有效，bit 1 灰尘样本有效 |
| 25 | 地刷灯亮判定 | UInt16，判定值 |
| 26–41 / 42–57 | 扫码信息 / 产品型号 | 各 32 字节 |
| 58 | 手动反馈 | bit 0–12 对应下列命令顺序 |
| 59–63 | 保留 | 填 0 |

测试完成时 PLC 应发布一份完整且稳定的快照，包含非零且在该站点内持久唯一的流水号和有效总判定。上位机按站点和流水号去重。现场需要在复位或下一轮开始前保留已完成快照，确保上位机在轮询间隔及预期断线期间能够读取。测试时序、联锁、传感器采样及真机判定由 PLC 执行。

### 配方区

`RecipeAddress` 为配方块起点。软件使用 FC16 一次写入 64 字，PLC 应在空闲且通过联锁后读取并应用配方。界面提示代表收到 Modbus 写寄存器确认。多字顺序和字符串编码与监控区一致。

参数界面的 16 个数值点位旁可编辑各自的保持寄存器起始地址。使用从 0 开始的协议地址，设置独立于配方值保存在本机。留空回到默认地址。下发时跳过已改址点位腾出的寄存器。未设置 `RecipeAddress` 时，配置完全部 16 个地址即可下发数值参数。产品型号和扫码字段通过原配方块传输。

配方参数页和新建配方窗口中的 Float32 电压、功率差上下限固定显示 4 位小数（例如 `28.0000`）。此格式仅影响显示，不改变数值的数据类型和下发编码；时间和整数字段保持原有显示格式。

两处窗口均可选择并保存「相机配方」：头灯-跑马灯对应 `switch 1`，头灯对应 `switch 2`，跑马灯对应 `switch 3`。命令中间为一个空格，不加行尾，不增加 PLC 寄存器。点击「启用配方」或「启用并下发 PLC」时，先通过设备管理页面中已连接的相机 TCP 发送对应命令。模拟模式同样发送。发送前会丢弃相机先前发来的数据：连接空闲约 50 ms 后才发送命令并开始等待回复；若相机 1 秒内持续发送数据，则不发送命令并提示。发送后最多等待 3 秒相机回复：返回 `OK`（不区分大小写，允许带行尾）才启用配方并下发 PLC。返回 `fail`、超时、回复无法识别、相机未连接或连接中断时，不启用配方，也不下发 PLC。旧配方默认选择头灯-跑马灯。

有自定义地址时，上位机按连续地址分段发送 FC16。PLC 应等全部数据到齐后再应用，分段写入失败时界面会提示可能已有部分参数写入。

| 字偏移 | 内容 | 类型或比例 |
| --- | --- | --- |
| 0 | 布局版本 | UInt16，固定为 1 |
| 1–4 / 5–8 / 9–12 | 电压 / 功率差 / 转速差，每组下限在前、上限在后 | Float32（V）/ Float32（W）/ Int32（r/min） |
| 13–16 | 正常及灰尘测试时间 | Int32，整数秒，原值下发 |
| 17–20 / 21–24 | 开机及档位动作时长 / 开机及档位间隔 | Int32，秒 × 10（0.1 秒单位） |
| 25 / 26 | 开机及档位次数 | UInt16 |
| 27–28 / 29–30 | 报警时间 / 跑马灯灭时间 | Int32，秒 × 10（0.1 秒单位） |
| 31 | 开始序号 | UInt16，从 1 开始计数 |
| 32–47 | 产品型号 | 32 字节 UTF-8 |
| 48 | 对比长度 | UInt16，由 PLC 按现场扫码规则解释 |
| 49–55 | 保留 | 填 0 |
| 56–63 | 保留 | 填 0 |

### 手动命令

手动窗口使用汇川 PLC 的 M 线圈作为按钮输入，用 Y 线圈反馈实际输出。按下用 FC05 写 1，松开用 FC05 写 0。窗口失去焦点或离开手动页时也会释放按钮。反馈通过 FC01 分组读取，通讯失败时显示「反馈未知」。清零失败后会尝试在通讯恢复时重发 0。PLC 需要自行处理联锁和通讯中断时的输出释放。

每个按钮旁的铅笔可编辑写入地址和反馈地址。支持汇川符号（如 `M50`、`Y10`）或从 0 开始的十进制线圈地址。Y 编号为八进制，Y0 的协议地址为 64512，Y10 为 64520。地址配置保存在本机数据库。真机操作手动输出需登录。地址换算见[汇川 H5U Modbus 协议说明](https://m.itlevne.com/data/upload/file/20210226/1614318717267400.pdf)。

| 写入 | 按钮 | 读取反馈 |
| --- | --- | --- |
| M50 | 通电 | Y0 |
| M51 | 压头气缸 | Y1 |
| M52 | 上压气缸 | Y2 |
| M53 | 通电平移 | Y3 |
| M54 | 开关气缸 | Y4 |
| M55 | 模式气缸 | Y5 |
| M56 | 灰尘模拟气缸 | Y6 |
| M57 | 地刷通电气缸 | Y7 |
| M58 | 编码器气缸 | Y10 |
| M59 | 扫码启动 | Y11 |

手动页按参考图显示以上十个按钮。原点表的 M60–M62 和 Y12–Y14 映射仍保存在软件中。

### 检测开关与复位

参数设置页的检测开关通过 `Commands` 配置写入线圈。打开用 FC05 写 1，关闭写 0。PLC 程序应按开关电平处理，并将实际状态写入监控区反馈字的以下位。界面按反馈显示开、关或未知。

三个检测开关右侧的铅笔可分别设置写入线圈和反馈线圈。可输入 `M` 写入点、`Y` 反馈点或从 0 开始的十进制线圈地址。设置保存在本机。写入留空使用 `Commands` 的地址，反馈留空使用下表的监控反馈位。填写反馈线圈后用 FC01 读取该线圈。保存地址只更新映射，操作开关时才写入 PLC。

| 位 | 命令 | 界面名称 |
| --- | --- | --- |
| 10 | `cameraOn` | 相机灯灭亮开关 |
| 11 | `cameraOff` | 相机灯灭开关 |
| 12 | `scanner` | 扫码开关 |

状态监控页「复位」旁的铅笔可设置独立的复位请求线圈，支持 `M` 编号或零基十进制地址。留空使用 `plc.json` 中的 `Commands.reset`，两处都为空时真机复位不可用。保存地址只更新本机映射。操作复位时，上位机用 FC01 检查上次请求是否已清除，再用 FC05 写 1。PLC 程序应校验设备状态和联锁，处理请求，清除请求位，并更新实际反馈。
